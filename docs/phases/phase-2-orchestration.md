## Цель

Превратить CLI-агента в ассистента: задачи ставятся голосом и текстом через OpenClaw / Telegram, агент помнит профиль пользователя, использует шаблоны навигации (App Cards) и проводит рискованные действия через формальный Approval Gate с инлайн-кнопками. Покрыть все 4 сценария PRD.

## Входные зависимости

- Фаза 1 закрыта (DoD выполнен).
- Ключ STT-провайдера (Whisper API или Deepgram).
- Тестовые аккаунты: Kaspi.kz, Aviata / Kaspi Travel, Ticketon, Chocofood.
- Сохранённые тестовые данные пассажира (не реальные паспортные данные на этапе разработки).

## Задачи

### Эпик A. Шлюз OpenClaw

- [ ] **P2-01 — Развернуть OpenClaw локально.** Установка рантайма, Control UI, конфигурация агента.
  *Приёмка:* Control UI доступен, тестовый агент отвечает.
- [ ] **P2-02 — Mobilerun как исполнитель OpenClaw.** Подключить GUI-агента из фазы 1 как инструмент/рантайм OpenClaw (сохраняя Allowlist, Audit Log, Payment Guard).
  *Приёмка:* задача из Control UI выполняется на телефоне.
- [ ] **P2-03 — Каналы Telegram (и опционально WhatsApp) через OpenClaw.** Перенос бота из P1-16 на шлюз.
  *Приёмка:* текстовая задача из Telegram проходит через OpenClaw до телефона.

### Эпик B. Голос

- [x] **P2-04 — Распознавание голосовых сообщений (STT).** Whisper API / Deepgram для аудиосообщений из Telegram.
  *Приёмка:* голосовая задача распознаётся и запускается без ручного ввода.
- [ ] **P2-05 — Мультиязычность ru / kk / en.** Смешанный ввод, словарь локальных топонимов, заведений и блюд (подсказки/постобработка).
  *Приёмка:* ≥ 90% корректного распознавания на наборе из 30 фраз на трёх языках.
- [ ] **P2-06 — Голосовые ответы (TTS), опционально.** Озвучка статуса/сводки.
  *Приёмка:* сводка непрочитанного приходит голосовым сообщением по запросу.

### Эпик C. Approval Gate

- [x] **P2-07 — Статус-машина сессии.** Состояния `RUNNING → WAITING_FOR_APPROVAL → APPROVED / CANCELLED / TIMEOUT → DONE`; сессия «замораживается» на экране до решения.
  *Приёмка:* состояние переживает перезапуск бота; по таймауту задача безопасно отменяется.
- [ ] **P2-08 — Инлайн-кнопки «Подтвердить» / «Отменить».** Скриншот финального экрана + сумма + кнопки в чат.
  *Приёмка:* после «Подтвердить» агент нажимает финальную кнопку, после «Отменить» — выходит без действия.
- [ ] **P2-09 — Классификатор рискованных действий.** Категории: «Финансы», «Отправка внешним адресатам», «Удаление данных». Правило для мессенджеров: обычные контакты — отправка по команде; новые и деловые чаты — черновик на согласование.
  *Приёмка:* каждая категория в тестах переводит сессию в `WAITING_FOR_APPROVAL`.

### Эпик D. Память и секреты

- [ ] **P2-10 — Долгосрочная память профиля.** Адреса («дом», «офис»), предпочтения в еде, частые контакты, «мой обычный заказ».
  *Приёмка:* «закажи мой обычный боул домой» использует сохранённые адрес и позиции.
- [ ] **P2-11 — Хранилище SecretRefs.** Зашифрованное локальное хранилище; LLM видит только плейсхолдеры (`{{secret:passport.number}}`), подстановка в поле ввода на уровне исполнителя.
  *Приёмка:* в логах промптов и Audit Log нет открытых секретов (автотест на утечку).
- [ ] **P2-12 — Профили пассажиров.** ФИО, документ, дата рождения через SecretRefs для билетных сценариев.
  *Приёмка:* данные пассажира подставляются в форму Aviata без попадания в контекст LLM.

### Эпик E. App Cards и структурированный сбор

- [ ] **P2-13 — Формат App Card и загрузчик.** YAML/MD-шаблон: пакет, ключевые экраны, селекторы, типовые пути, известные ловушки; подмешивание в контекст по активному приложению.
  *Приёмка:* загрузчик подхватывает карточку при открытии приложения.
- [ ] **P2-14 — App Cards: 2ГИС, Яндекс Go, Chocofood.**
  *Приёмка:* снижение среднего числа шагов/токенов ≥ 20% vs без карточки на тестовом наборе.
- [ ] **P2-15 — App Cards: Kaspi, Aviata, Ticketon.**
  *Приёмка:* то же, для билетных сценариев.
- [ ] **P2-16 — mobile-use (Minitap) для сбора данных в JSON.** Сравнение цен на билеты, выгрузка списка сообщений с нескольких экранов.
  *Приёмка:* «сравни рейсы в Алматы на пятницу утром» возвращает валидный JSON-список рейсов.

### Эпик F. Сценарии 2 и 4 + оплата

- [ ] **P2-17 — Сценарий «Бронь столика».** 2ГИС / Яндекс Карты → онлайн-форма брони или WhatsApp администратору; подтверждение ресторана и времени у пользователя перед фиксацией.
  *Приёмка:* «забронируй столик на двоих на 20:00 в тихом итальянском кафе» доходит до подтверждения пользователем.
- [ ] **P2-18 — Сценарий «Билеты».** Aviata / Kaspi Travel / Ticketon: маршрут, даты, фильтры, выбор места, подстановка пассажира, остановка перед оплатой.
  *Приёмка:* «найди и оформи билет в Алматы на пятницу утром» доходит до Approval Gate со скриншотом даты, рейса, ФИО и суммы.
- [ ] **P2-19 — Оплата через Kaspi invoice.** Выбор способа «Выставить счёт в приложении Kaspi» по номеру телефона; агент не заходит в банковское приложение.
  *Приёмка:* после подтверждения пользователю приходит Kaspi-пуш; агент сообщает о статусе.

### Эпик G. Качество

- [ ] **P2-20 — Регресс-набор 4 сценариев и замер KPI.** Расширить набор из P1-17 до всех сценариев, голосовых команд и Approval Gate.
  *Приёмка:* Task Success Rate по типовым сценариям с App Cards ≥ 85%; результаты в [PROGRESS.md](../PROGRESS.md#4-трекер-kpi).

## Deliverables

- OpenClaw-шлюз с каналом Telegram (текст + голос).
- Approval Gate со статус-машиной и инлайн-кнопками.
- Память профиля + зашифрованные SecretRefs.
- App Cards для 6 приложений, интеграция mobile-use.
- Все 4 сценария PRD до точки контроля человеком.

## Критерий готовности (DoD из PRD)

> Постановка задачи голосом через Telegram-бота с получением скриншота чекаута на одобрение.

## Риски фазы

| Риск | Митигация |
| :--- | :--- |
| Качество STT для казахского языка | Сравнить Whisper и Deepgram, словарь подсказок, подтверждение распознанной команды |
| Антифрод-детекция ADB в Kaspi / билетных приложениях | Kaspi — только invoice-сценарий; фиксировать блокировки в журнале рисков |
| Утечка секретов в контекст LLM | SecretRefs + автотест на утечку (P2-11) |
| App Cards устаревают при обновлениях приложений | Версионировать карточки по версии приложения |
