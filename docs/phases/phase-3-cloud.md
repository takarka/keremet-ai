# Фаза 3 — Cloud 24/7: облачные смартфоны Android и iOS

> Общий план: [PLAN.md](../PLAN.md) · Прогресс: [PROGRESS.md](../PROGRESS.md) · Предыдущая фаза: [phase-2-orchestration.md](phase-2-orchestration.md)

| **Сроки** | Недели 7–10 |
| **Приоритет MoSCoW** | Could Have |

| **Задач** | 16 (`P3-01` … `P3-16`) |

## Цель

Перенести агента с домашнего ноутбука в облако: задачи выполняются 24/7 при выключенном ноутбуке на облачных Android и iPhone, OTP-коды принимаются автоматически, агент работает проактивно по расписанию, а успешные сценарии повторяются детерминированно без LLM.

## Входные зависимости

- Фаза 2 закрыта (DoD выполнен).
- Аккаунт и тариф Mobilerun Cloud, API-ключ `dr_sk_...`.
- Сервер/VPS для OpenClaw-шлюза (или облачный хостинг шлюза).
- Номер/eSIM для облачных устройств, решение по переносу аккаунтов приложений.

## Задачи

### Эпик A. Подключение облака

- [ ] **P3-01 — Аккаунт Mobilerun Cloud и ключ API.** Ключ `dr_sk_...` хранится только в секретах (SecretRefs / переменные окружения сервера).
  *Приёмка:* тестовый вызов API выдаёт список доступных устройств.
- [ ] **P3-02 — Абстракция DeviceProvider.** Единый интерфейс `local_adb` / `cloud_android` / `cloud_ios`, выбор устройства в конфиге и на уровне задачи.
  *Приёмка:* одна задача запускается на локальном и облачном Android без изменения кода сценария.
- [ ] **P3-03 — Облачный Android.** Провижининг выделенного устройства, установка приложений из allowlist, вход в аккаунты, постоянная сессия.
  *Приёмка:* сценарии фазы 2 проходят на облачном Android.
- [ ] **P3-04 — Облачный iPhone.** Подключение физического iPhone, адаптация действий и App Cards под iOS-интерфейс.
  *Приёмка:* сценарии «мессенджер» и «доставка» проходят на iPhone.
- [ ] **P3-05 — Шлюз OpenClaw 24/7 на сервере.** Деплой, перенос памяти и SecretRefs, автоперезапуск, бэкапы.
  *Приёмка:* задача из Telegram выполняется при выключенном ноутбуке.

### Эпик B. OTP и проактивность

- [ ] **P3-06 — Автоматический приём OTP.** Чтение SMS-кодов с виртуальной eSIM и ввод при авторизации в сервисах доставки и билетов; OTP не попадает в контекст LLM.
  *Приёмка:* повторный логин в Wolt/Aviata проходит без участия пользователя.
- [ ] **P3-07 — Планировщик фоновых задач.** Cron-подобные триггеры, управление расписанием из чата.
  *Приёмка:* пользователь создаёт/удаляет расписание командой в Telegram.
- [ ] **P3-08 — Утренняя сводка (08:30).** Сводка ночных сообщений из мессенджеров.
  *Приёмка:* сводка приходит ежедневно в 08:30 по Алматы.
- [ ] **P3-09 — Мониторинг статуса рейса.** Проверка статуса купленного рейса и уведомление об изменениях.
  *Приёмка:* при изменении статуса тестового рейса приходит уведомление.

### Эпик C. Replay Macros

- [ ] **P3-10 — Запись макросов.** Сохранение успешной траектории как детерминированного сценария с параметрами (контакт, текст, адрес).
  *Приёмка:* из Audit Log успешной задачи формируется макрос.
- [ ] **P3-11 — Воспроизведение с валидацией.** Проверка ожидаемого экрана на каждом шаге, fallback на LLM при расхождении; Payment Guard и Approval Gate активны.
  *Приёмка:* повтор задачи через макрос — без вызовов LLM при неизменном UI, стоимость ≈ $0.

### Эпик D. Эксплуатация и безопасность

- [ ] **P3-12 — Мониторинг и алерты.** Health-check устройств и шлюза, алерты о сбоях, дашборд метрик задач.
  *Приёмка:* при отключении облачного устройства приходит алерт в течение 5 минут.
- [ ] **P3-13 — Allowlist и Audit Log в облаке.** Централизованное хранение журнала траектории, ротация, доступ только владельцу.
  *Приёмка:* журнал облачных задач доступен и восстанавливает путь задачи.
- [ ] **P3-14 — Регресс безопасности.** Тесты: перехват всех платёжных экранов, отсутствие секретов/OTP в логах LLM, блокировка приложений вне allowlist, отсутствие root/jailbreak и обхода FLAG_SECURE.
  *Приёмка:* Zero Unauthorized Spend — 100% перехват на обеих платформах.
- [ ] **P3-15 — Финальный прогон KPI.** Все сценарии на облачном Android и iPhone.
  *Приёмка:* KPI PRD достигнуты, итог в [PROGRESS.md](../PROGRESS.md#4-трекер-kpi).
- [ ] **P3-16 — Эксплуатационная документация.** Runbook: подключение устройств, ротация ключей, восстановление сессий, разбор инцидентов.
  *Приёмка:* runbook покрывает все алерты из P3-12.

## Deliverables

- Облачный контур: шлюз 24/7 + облачные Android и iPhone.
- Авто-OTP, планировщик, утренняя сводка, мониторинг рейсов.
- Replay Macros с валидацией экрана.
- Мониторинг, регресс безопасности, runbook, финальный отчёт KPI.

## Критерий готовности (DoD из PRD)

> Агент выполняет задачи 24/7 при выключенном ноутбуке на обеих платформах (Android и iOS).

## Риски фазы

| Риск | Митигация |
| :--- | :--- |
| Ограничения/стоимость облачных iPhone | Ранний пилот на 1 устройстве, оценка бюджета до закупки |
| Блокировка аккаунтов при смене устройства/IP | Резидентский IP, постепенный перенос аккаунтов |
| Антифрод-детекторы на облачных устройствах | Не использовать root/jailbreak; фиксировать несовместимые приложения |
| Хрупкость Replay Macros при обновлениях UI | Валидация экрана на каждом шаге + fallback на LLM |
