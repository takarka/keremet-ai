## Цель

Получить работающий GUI-агент, который по текстовой команде из терминала Windows (и из простого Telegram-бота) выполняет действия в реальных приложениях на Android-телефоне и **безусловно останавливается** перед любой оплатой.

## Входные зависимости

- Android-смартфон (Android 10+) с включённым режимом разработчика.
- Ноутбук Windows 10/11 с правами администратора.
- API-ключ хотя бы одного LLM-провайдера (Claude / OpenAI / Gemini).
- Тестовые аккаунты в WhatsApp, Telegram, 2ГИС, Wolt или Яндекс Go; карта в агрегаторе доставки привязана вручную.
- Токен Telegram-бота (BotFather).

## Задачи

### Эпик A. Окружение и подключение устройства

- [x] **P1-01 — Каркас репозитория и Python-окружение.** Python 3.11+, venv/uv, базовая структура каталогов (см. [PLAN.md](../PLAN.md#5-структура-репозитория-ориентир)), `.gitignore`, `.env.example`.
  *Приёмка:* `python -m agent --help` запускается в чистом окружении.
- [x] **P1-02 — ADB по USB.** Установить Android platform-tools, USB-драйверы, включить USB debugging.
  *Приёмка:* `adb devices` показывает устройство в статусе `device`.
- [ ] **P1-03 — ADB по Wi-Fi.** Настроить беспроводную отладку (`adb pair` / `adb tcpip 5555`), описать переподключение.
  *Приёмка:* агент работает с отключённым кабелем в одной Wi-Fi-сети.
- [x] **P1-04 — Mobilerun Framework + Portal APK.** `pip install mobilerun`, установка `Mobilerun Portal`, включение Accessibility Service.
  *Приёмка:* из Python получаем XML-дерево текущего экрана и выполняем `tap`, `swipe`, `type`, `open_app`.
- [ ] **P1-05 — Конфигуратор LLM-провайдеров.** Единый конфиг (Claude / GPT / Gemini), выбор модели через `.env`/CLI-флаг, ключи только из переменных окружения.
  *Приёмка:* одна и та же задача запускается на двух разных провайдерах сменой одного параметра.

### Эпик B. Ядро агента

- [x] **P1-06 — CLI запуска задач.** `agent run "<задача на естественном языке>" [--vision] [--model ...] [--dry-run]`.
  *Приёмка:* команда из терминала Windows выполняет простую задачу («открой Telegram») на телефоне.
- [ ] **P1-07 — Гибридный анализ экрана.** По умолчанию A11y XML-дерево; автоматическое или ручное (`--vision`) включение скриншотов для нестандартных экранов.
  *Приёмка:* на обычном экране шаг ≤ 500 мс без скриншота; на кастомном экране агент переключается на vision.
- [x] **P1-08 — Телеметрия задачи.** Для каждого запуска: число шагов, время, токены, стоимость, итог (успех/ошибка/остановлен).
  *Приёмка:* после каждого запуска пишется JSON-отчёт, из которого считаются KPI.

### Эпик C. Безопасность MVP

- [x] **P1-09 — App Allowlist.** Конфиг белого списка пакетов; блокировка `open_app` и переходов в системные настройки безопасности / приложения вне списка.
  *Приёмка:* попытка открыть приложение вне списка прерывает задачу с понятным сообщением.
- [x] **P1-10 — Журнал траектории (Audit Log).** Каждое действие + скриншот/XML-снимок сохраняются локально с таймстампом и ID задачи.
  *Приёмка:* по журналу можно восстановить пошаговый путь любой задачи.
- [ ] **P1-11 — Стоп-кран оплаты (Payment Guard).** Детектор финальных платёжных кнопок («Оплатить», «Купить», «Перевести», «Pay», «Төлеу» и др.) на уровне исполнителя, до вызова `tap`. Безусловная остановка + скриншот пользователю.
  *Приёмка:* в 100% тестовых прогонов чекаута tap по кнопке оплаты не выполняется.

### Эпик D. Первые сценарии

- [ ] **P1-12 — Сценарий «Ответ в WhatsApp».** Найти контакт, прочитать последние сообщения, набрать и отправить ответ.
  *Приёмка:* «Ответь Арсену в WhatsApp, что буду к 19:00» выполняется end-to-end.
- [ ] **P1-13 — Сценарий «Telegram: ответ и сводка».** Ответ в чат + сводка непрочитанных сообщений.
  *Приёмка:* агент возвращает текстовую сводку непрочитанного по 3+ чатам.
- [ ] **P1-14 — Сценарий «Корзина доставки» (Wolt / Яндекс Go).** Проверка адреса, поиск ресторана и позиций, добавление в корзину, применение промокода, переход к чекауту → остановка P1-11.
  *Приёмка:* пользователь получает скриншот корзины с итоговой суммой, оплата не нажата.
- [ ] **P1-15 — Навигация в 2ГИС.** Поиск заведений по кухне, рейтингу и району, извлечение карточки (название, рейтинг, адрес, телефон).
  *Приёмка:* «найди итальянское кафе с рейтингом от 4.7 рядом» возвращает список из 3+ мест.

### Эпик E. Канал управления

- [x] **P1-16 — Простой Telegram-бот (текст).** Приём текстовой задачи, запуск агента, отправка статуса и скриншотов; доступ только для whitelisted user ID.
  *Приёмка:* задача из Telegram выполняется на телефоне, скриншот чекаута приходит в чат.

### Эпик F. Качество и документация

- [ ] **P1-17 — Набор тест-сценариев и базовый замер KPI.** 10–15 повторяемых задач по P1-12…P1-15, скрипт прогона, сводка Success Rate / latency / cost.
  *Приёмка:* таблица baseline-KPI занесена в [PROGRESS.md](../PROGRESS.md#4-трекер-kpi).
- [ ] **P1-18 — README по установке и запуску.** Пошагово: драйверы, ADB, Portal, `.env`, первый запуск.
  *Приёмка:* второй человек поднимает окружение по README без помощи.

## Deliverables

- CLI-агент `agent run` + Telegram-бот (текст).
- Модули Allowlist, Audit Log, Payment Guard.
- 4 рабочих сценария: WhatsApp, Telegram, доставка (до чекаута), 2ГИС-поиск.
- Отчёт baseline-KPI.

## Критерий готовности (DoD из PRD)

> Успешное выполнение команды из терминала Windows на реальном Android-телефоне.

Дополнительно: сценарии «ответ в мессенджере» и «сборка корзины доставки» проходят end-to-end, Payment Guard перехватывает 100% тестовых чекаутов.

## Риски фазы

| Риск | Митигация |
| :--- | :--- |
| Нестабильность Wi-Fi ADB | Автопереподключение, fallback на USB |
| Приложения с FLAG_SECURE дают чёрный скриншот | Работать по XML-дереву; банковские приложения вне scope |
| Изменение UI приложений между версиями | Фиксировать версии приложений на тестовом телефоне |
| Высокая стоимость при частом `--vision` | Vision только по триггеру, телеметрия стоимости (P1-08) |
